# 剪映草稿与素材

## 选择工作入口

- 用户要求剪映专业版本地草稿时，先确认目标客户端和当前草稿位置，优先用现有项目的正常入口另存并编辑。仅有 CapCut 网页项目或 STDraft 数据时，按对应客户端验证导入能力。账号授权或云端上传按当前任务范围处理。
- 自动构建时，先在目标版本里做一份短测试草稿，验证导入、原始媒体裁切、文本、轨道叠放、原生关键帧和导出。社区草稿库与本地注册格式会随版本变化。读取不到草稿正文时，通过应用另存或导出可编辑副本，或以已确认的时间线数据新建。明确标明重建来源与覆盖范围。
- 将生成和安装拆开。先在暂存目录检查 JSON、素材引用和字体，再用应用支持的方式导入或注册。用唯一草稿名，避免覆盖用户项目。如果当前方式需要直接改草稿注册文件，先保留可恢复的备份并避免与应用并发写入。安装后从应用首页重开，确认保存后仍能再次打开。

## 保留可编辑性

| 轨道职责 | 建议保留 |
| --- | --- |
| 录屏 | 原始文件、源入出点、独立缩放和裁切 |
| 实拍 | 原始文件、源入出点、可替换的 B-roll 或画中画 |
| 包装 | 背景、边框、章节提示、箭头和账号遮挡按用途分开 |
| 文本 | 章节编号、标题、说明和字幕为原生文字，混排保留各语言字体 |
| 声音 | 原声、音乐、章节音效、操作音效按用途分轨 |

用整数帧记录时间线，草稿 API 需要其他单位时在边界统一换算。检查每个片段的源区间、目标区间、轨道内重叠和尾帧。生成图形时保留独立的透明叠层。临时抽帧、包装、音频和字体一旦被引用就移到稳定位置。换机器交接时测试重新链接，确认字体可随项目分发或提供安装说明所需的字体名称。

验收时在副本里实际改一条字幕、裁一个录屏片段、隐藏一层包装。声音项目再独奏一条声音轨，确认项目能独立精修。录屏含账号、密钥或客户信息时检查所有裁切、缩放和转场后的遮挡。
