# 原生草稿与分层验收

## 选择入口

- 剪映专业版本地草稿、CapCut 网页项目及 STDraft 分别按目标客户端处理。优先对已有工程另存；只有网页草稿时，先验证目标版本能否承接。网页账号授权和素材上传以用户任务范围为准。
- 自动生成前，拿代表性小段做目标版本验证：原始素材裁切、可改原生文字、字号、层序、关键帧、导出。有透明素材再验证 Alpha 与色彩。社区库与草稿格式随版本变化；小样失败时先调整构建方式或直接用客户端编辑。
- 暂存区生成和检查草稿，再通过应用入口安装或导入。使用唯一项目名；若当前方法需要写注册数据，先做可恢复备份并避免与客户端并发写入。素材与字体依赖落到稳定位置，按交接场景测试重链。

## 轨道拆分

| 职责 | 编辑方式 |
| --- | --- |
| 口播、录屏、实拍 | 原始文件和源入出点，分别可裁切、调画幅、替换；按需要分离口播原声 |
| 字幕、标题、关键词、按钮标注 | 剪映原生文字。短段验证混排、字号、字重、换行、安全区 |
| 人物层、遮挡、箭头、卡片、装饰 | 可独立关闭和定位；优先原生简单图形与关键帧，复杂层按功能独立预渲染 |
| 音频 | 对白、环境声、配乐和音效分轨；独奏测试，防止重复原声 |
| 参考预览 | 用于对比；剪映草稿应保留独立轨道，能替换任何需要复剪的原片 |

同类且同时编辑的图形可以共用一轨。必须单独控制的内容分开，例如字幕底板与字幕字形、人物遮挡与背景图案。复杂透明层在剪映可移动、裁切、变速或替换，内部节点和粒子回源改。对需要逐对象修改的内容，继续拆层或重做原生。转场和放大后的敏感信息仍需被遮住。

## 客户端实测

从首页重开项目，预览前、中、后段，核对素材、字体、长度和关键帧。另存测试副本，实际改一条字幕、裁一个原素材、隐藏一层包装、移动一次原生关键帧；有声音再独奏原声。有导出任务时对比客户端预览与最终文件，报告成功测试的操作和受限项。仅检查 JSON、文件存在或叠层可播放，都不能证明草稿可精修。

## 整理主时间线

在制作前规划章节和职责。默认把每章画面组织为原生复合片段，双击进入内部精修；主线另留字幕底板、字幕、口播原声、音乐、音效等必要轨道，未使用的职责不建空轨。完整影片、章节片段和音频使用清楚的名称。内部同类且不重叠元素可合轨，但不得为减轨合并需要单独控制的对象。

整理前保留可恢复的工作副本，使用当前最新工程状态。章节内保留原始媒体、原生文本、关键帧和复杂层的源工程映射。主字幕及声音仍在主线时，移动章节必须同步关联内容；交接说明具体选中/联动方法，不声称它们会自动随章节移动。

整理前后核对时长、有效文字片段数、源入出点、声音与关键帧；不要用未引用的材质池数量冒充可编辑文字数量。运行 `scripts/audit_draft.py` 可获取按实际 segment 引用计算的统计，完整功能仍需客户端实测。结构与回归风险见 [组件规范](component-contracts.md)。

必须测试双击一章进入、修改并恢复一条标题、返回主线、连续播放跨章和实际导出。若原生嵌套不兼容，先修复或改用客户端生成，不得交付空画面工程。无法实现时明确说明限制，提供保留全部可编辑层的整理版及可选方案；不能以烘焙整章视频掩盖失败。
