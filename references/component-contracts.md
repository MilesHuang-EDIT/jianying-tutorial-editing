# 可复用组件与版本边界

复用组件的编辑职责、数据结构和验收方法，不把单片视觉定成所有视频的皮肤。现有工程可作为已验证样本，但不能宣称在新剪映版本已通过。每次记录客户端版本、构建入口和小样结果；只复制有权分发的自有代码与素材。

| 组件 | 必须保留的编辑能力 | 验收 |
| --- | --- | --- |
| 章节标题/问题卡 | 原生标题、编号、底板与进出场关键帧分别可改 | 改长标题后仍无裁切，文字不被底板/遮罩挡住 |
| 关键词/解释标注 | 原生文字，位置、强调时刻与箭头目标可调 | 对齐实际语义或点击；关闭后原片完整 |
| 页面/录屏展示 | 原始素材及源入出点，局部放大与画幅关键帧可改 | 点击与结果可读，不用截图假冒未录到操作 |
| 人物与 B-roll 组合 | 人物、素材、图形按所需遮挡独立 | 可替换素材；人像处理遵循实际 Agent Motion 规则 |
| 字幕 | 原生逐句文字，底板单独控制 | 改内容、改时间，混排字体和安全区正确 |
| 章节容器 | 原生复合片段，含原始素材、标题和图形 | 双击进入，改字/关键帧，返回主线并导出 |
| 声音 | 对白、音乐、音效分轨，音量和起止可改 | 独奏无重复人声；静音模式无多余声音 |

组件实现顺序：从目标版本读取一个原生样本 → 封装参数（文字、素材、时长、版式、动效）→ 短段验证 → 复用到同片。对复杂三维层同时留源入口，不能声称在剪映里可编辑所有内部节点。暂不支持的组件说明限制，不以扁平渲染冒充实现。

## 原生复合片段：已验证结构线索

以下是一次本地剪映版本的实测结构线索，**不是跨版本通用 API**。使用前先用目标客户端建立小样，比较结构，再生成暂存副本。

- 主轨 segment 的 `material_id` 引用占位 `materials.videos[]`。该样本中视频材质 `extra_type_option: 2`，路径为空，时长等于子草稿；它不是缺失外部媒体。
- segment 的 `extra_material_refs` 引用 `materials.drafts[]` 中 `type: "combination"` 的组合材质。组合材质内 `draft` 保存完整子草稿，并关联独立的子草稿 ID、配置与路径。不能把 `type: "draft"` 材质直接作为主轨视频材质；曾出现项目能开但画面为空。
- 原生样本还包含 `subdraft/<child-id>/` 下的草稿、配置等文件。用目标版本产生的完整样本补齐必要字段，不仅拼接上述简化字段。
- 整理时子片段目标时间减去章节起点；媒体源入点保持真实映射。跨章节裁切若改变源入点，要按实际变速映射，并核对关键帧的时钟定义。不能只改时长。
- 主字幕与音频留主线时，不在子草稿重复；保留总时长、视觉层序和原始媒体引用。打包外部媒体时忽略合法的空路径占位材质，但检查所有非空外部路径。
- 另存必须同步更新实际版本使用的内容与注册元数据 ID，避免覆盖当前工程。原生保存可能更新不同文件或加密内容；先确定当前编辑状态的可信来源，不能用旧 `draft_content.json` 悄悄覆盖用户最新修改。

验证过的“六条主轨”只是一个项目实例，不是数量指标。章节内部需要多少层由效果与编辑任务决定；主线上能方便换段、改字幕、调声音，内部能继续精修才是目标。

## 关键帧与层序回归点

- 在目标版本确认关键帧是片段相对、素材相对还是其他时钟；某次本地格式的 `common_keyframes` 需要加 `source_timerange.start`。不能把该约定套到所有库。
- 为变换状态显式设置需要的起止值，包括恒定的 Y、scaleY 等；漏写常量可能出现暂停预览正常、连续导出继承前段变换而上下抽动。
- 原生文字与底板的层序使用目标版本实际规则；极大 `render_index` 不能保证文字在顶层。进入、停稳、退出及遮罩交界都检查。
- JSON 引用完整只说明数据结构可检查；必须连续播放并检查客户端导出，才可判定无抽动、无半遮挡。
