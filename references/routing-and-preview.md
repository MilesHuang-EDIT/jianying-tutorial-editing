# 分流、依赖和风格预览

## 调用前核实

总控是协调工作流，不提供虚构的跨 skill 自动调用 API。通过当前会话的 skill 目录找到 `video-shotcraft`；通过用户指定或本机已安装 checkout 找到 Agent Motion。记录实际入口、版本/commit（能取得时）、适用许可与可用依赖。同名项目不能未经比较视为相同版本。

- Agent Motion：读 checkout 的 `AGENTS.md`、`.agents/skills/motion-craft/SKILL.md`；涉及 SRT/口播时再读 `.agents/skills/srt-reference-to-three/SKILL.md`，按该版本要求先分析后制作。分阶段规则按其分页读取，不用摘要替代。
- Shotcraft：读实际 `SKILL.md`。单镜头读取准确卡片和 demo；完整片按已选模式读取 pipeline 或 guided 流程。
- 本包只分发自己的协调规范，不捆绑上游代码、模板、付费素材或许可。Agent Motion 当前版本的商业授权依其实际条款核验，同一任务复用有效核验，不把公开仓库当成商业许可。此处写集成规范无需启动商业视频制作或索取许可证。
- 用户要求安装时使用可用安装流程。缺失、受限或不支持的能力明确标记，不能声称调用成功；提出具体可用替代路线并沿用已有授权。

## 模式与确认

用户选视频类型不等于选 Shotcraft 完整宣传片模式。总控为教程/口播分配 B-roll 或局部动效时优先用单镜头入口；若确实委托完整宣传片，按其入口做最小只读检查，并在模式未定时请用户选择。已选模板、指定卡片或自主创作的授权传给下游，不再次询问同一件事。

风格预览是本总控默认的制作前节点。尽可能把类型、视觉方向、候选镜头和需要的模式选择放在一份可审阅方案中。若选择 Shotcraft 共同创作，仍遵守其后续确认节点；不能以总控一次确认绕过。若用户明确要求全权决定，则记录自主模式并连续执行，预览作为执行记录展示。付费生成和发布仍遵守各自明确授权边界。

## 推荐动效

先理解真实素材和产品视觉，再查 `gallery/api/library.json` 与 `references/shots/`，核对卡名、style-key、配方和准确 demo 源码；把实际动态样片入口附给用户。推荐表包含：

| 内容/时段 | 真实卡名与变体 | 为什么合适 | 运动与停留 | 剪映内可改 / 回源可改 |
| --- | --- | --- | --- | --- |
| 按本片填写 | 按索引核验 | 解释它帮助观众理解什么 | 进场、阅读、退场 | 字幕/位置与内部三维节点分别说明 |

推荐通常 3–5 个，单镜头或素材少时按需要减少。要有取舍，不能把所有炫技塞进教程。说明采用的是运动语法，字体、颜色和材质按本片统一。

## 风格预览实际产物

1. 提取用户品牌和真实页面的字体、色彩、间距、圆角、层级；用户指定的字体优先。网页用浏览器真实截图，不能手绘假界面充当软件实操。
2. 用最终文案长度和实际素材做 2–3 张目标画幅 styleframe：开场、典型正文、最密信息。可以用下游支持的场景静帧或真实 HTML/CSS 构图截图，不要求先渲染整片。
3. 实际输出 PNG/JPEG，并在回复中展示图片，附候选动效用途；只写“科技风、卡片入场”不算预览。检查字形、行距、对齐、对比度及安全区。
4. 确认或已有自主授权后进入短样段。静帧确认视觉不等于运动已通过；样段还要看连续运动、阅读时间和声音。不要在用户尚未确认且未授权自主时先完成整片再补预览。

## 共用交接数据

用 [handoff.json](../templates/handoff.json) 的结构按项目填写，不把示例当成实际素材。所有工具复用同一帧时钟，零基整数帧、区间 `[in, out)`；宽高、帧率与时间精度按真实项目。源文件保留源入出点、变速映射，字幕映射后统一贴帧，避免逐片累计取整。

先约定镜头归属：口播 Agent Motion 主导，Shotcraft 负责分配的 B-roll；教程反之，人物段落再接 Agent Motion。两个工具都可以提出镜头建议，但不得改掉已锁定原声或操作证据。总控维护唯一最终字幕和混音；中间预览有混音时标为参考并禁止重复叠加。原声、静音或音乐模式沿用用户选择。
